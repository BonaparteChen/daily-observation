AI 技巧 / 操作指南

两个 AI 编程任务，先分开文件，再分开聊天

独立目录能分开文件改动，却不会自动分开数据库和外部服务。

操作指南

常青方法 · 11月19日Git命令验证
2026年11月19日编

来源 ↓

两个会话同时改项目时，聊天记录分开，不代表磁盘上的文件分开。B站作者技术爬爬虾在视频配套文字稿 ↗中讨论了 Fork 与 worktree 的差别。这里把问题收窄到可复现的一步：用 Git 为两个任务准备独立目录，不依赖某个 AI 客户端的按钮。

先在已经有提交的 Git 项目中运行 git status --short，确认自己知道哪些改动尚未提交。下面的目录和分支名须尚未存在；从同一个 HEAD 创建两个工作目录，未提交的改动不会自动复制进去。

git worktree add -b ai/task-a ../ai-task-a HEAD
git worktree add -b ai/task-b ../ai-task-b HEAD

分别进入两个新目录，在其中运行以下两条命令。验收点是路径分别指向 ai-task-a、ai-task-b，分支分别为 ai/task-a、ai/task-b；再让对应的 AI 会话选择各自目录。若客户端不能确认工作目录，先别开始修改。

git rev-parse --show-toplevel
git branch --show-current

本刊在 Windows、Git 2.56.0.windows.4 的独立测试仓库中执行了上述结构的命令，并分别修改同名文件：A、B 目录各自保留不同内容，原目录仍为基线，git status --short 为空。验证的是 Git 文件分离；没有运行 AI 客户端，也没有验证模型是否遵守目录范围。

Git 官方文档 ↗说明，多个工作目录仍属于同一仓库。它们不会自动隔离端口、数据库、凭据或外部服务，也不保证最后能无冲突合并。任务完成后先在各目录用 git diff 审阅改动，再分别提交、测试和决定合并；不要把“两个目录没互相覆盖”当作最终结果已经兼容。
