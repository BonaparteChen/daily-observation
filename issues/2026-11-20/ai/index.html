把资料整理成 JSON，先验字段，再核原文

文档方法

常青方法 · 11月20日核官方文档
2026年11月20日编

来源 ↓

把一段资料交给模型整理成表格，最容易混淆两件事：结果能否被程序读取，以及填进去的内容是否有依据。Gemini 的结构化输出文档允许用 JSON Schema 规定字段和类型，并要求应用继续验证返回值。官方文档 ↗

可先拿一小段不含私人资料的文字，限定输出“事项、日期、原文依据”三个字段；没有日期就允许返回 null，并在任务说明里要求不要补猜。把这份 schema 配到所用 API 的结构化输出参数，而不只是在提示词末尾写“请输出 JSON”。接口与模型需按当前官方示例选择；这里不提供未经调用验证的兼容性承诺。

验收分两轮：程序先检查 JSON 能否解析、字段是否齐全、值的类型是否正确；人再逐项把日期和事项对回原文。一个语法正确的错误日期仍然是不合格结果。若要限制字符串长度或数组重复，还要核对服务支持的 schema 子集并在应用端检查。以上是依据文档设计的操作方法，本刊未调用 Gemini API，不报告准确率或提速幅度。

下面是编辑设计的最小 schema 示例，供核对字段使用，未执行模型请求：

{"type":"object","properties":{"event":{"type":"string"},"date":{"type":["string","null"]},"evidence":{"type":"string"}},"required":["event","date","evidence"],"additionalProperties":false}

教学输入“说明会定于11月25日举行，年份待定”，验收时就不应接受模型擅自补上的年份；输入“时间另行通知”，日期字段应为空。即使这两次输出都通过字段检查，也仍须核对原文。这是验收示例，不是实测结果。
