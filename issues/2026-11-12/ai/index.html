一条链接的权限，可能比代码更要紧

35,578 个应用可以在不登录的情况下打开。安全公司 Claroc 调查 Grok Build 时，还发现 xAI（Claroc 称其现名 SpaceXSI）与 X 员工创建的 24 个应用向任何人开放，其中包括一份标为机密的新员工入职计划。用户让 AI 写好应用，再按下发布按钮，谁被允许走进来？Claroc 销售相关安全服务。[1]

Claroc 在自己的账号中看到，发布面板预选了“持有链接的任何人”。在它自建的“4 人销售团队”测试应用里，任何一个 Google 账号都能登录，读到全部客户记录，还能改、能删。Grok 写的代码先把来人加进团队，再检查他在不在团队里。研究者只在自家应用上做了写入测试。[1]

Ars 报道取得的公司答复强调，创作者选择分享前，应用并不公开。发布面板的默认选项则决定了分享后谁能访问：账号登录和数据授权，需要分别设置。截至发稿，xAI 尚未发布公开安全通告。[1][2]

锁住运行环境，也得检查里面的软件

另一份材料把问题带到了服务器里。NEAR AI 在 11 月 9 日报告，11 月 8 日的事件涉及推理引擎 SGLang 的远程代码执行漏洞。公司确认约 100 个账户信息与旧部署中的 18 个代理受到影响，两个客户出现在日志中的 API 密钥已撤销。[3][4]

NEAR AI 称，它未发现已存储的私人聊天和上传文件被读取的迹象；受影响服务器当时处理中的请求则可能被看到，包括机密模式请求。18 个旧代理运行在可信执行环境之外，涉及另一处部署。[3]

机密计算隔开运行环境与宿主、运营者；运行在环境内部的软件如果有漏洞，保护边界仍可能被穿过。按官方报告的解释，旧账户、日志里的密钥与正在处理的请求，各有需要清理和检查的地方。[3]

测试亮绿灯，也可能一次都没跑

还有一种失误出现在开发者交活之前。署名 aiks_yuan 的作者实测，在五个类组成的 Java 演示项目里，把分层约束写成 ArchUnit 测试，再用 Claude Code 的 Stop hook 在结束前执行。作者发现，自己的配置在 Maven Surefire 3.5.3 下出现“0 个测试、构建成功”；换版本或改写测试后，违规才正常被拦下。[5]

这次作者实测使用 Claude Code 2.1.299、JDK 17 与 ArchUnit 1.5.1。门禁还有两处会悄悄失效：作者的脚本在第二次触发时直接放行，不再跑测试；而 hook 报错里只要出现 "No such file or directory"，Claude Code 就会把它当成『脚本缺失』，不再拦截。作者事后手动运行 mvn test 复检。写下规则、安装检查工具和确认规则真正执行，是三个步骤。[5]

省下写代码的时间，检查责任没有消失

分享设置、服务端依赖和开发门禁分别出了问题。一个人可以很快做出应用，交付时仍要知道它向谁开放、依靠什么服务，以及检查是否真的运行。

对团队来说，快速做出内部工具是收益；权限审核、依赖维护与失败样本检查则是相应的工作。产品提供者可以把安全选项做得更明确，使用团队也需要为每个应用指定维护者。

应用生成完成后，还有三个问题值得实际走一遍：陌生账号能进吗，旧数据还留在哪里，故意放入一个错误时检查会失败吗？

fp4 和 fp16 打成平手：六个端点 240 道题，没测出差别

OpenRouter 11 月 11 日发布的作者实测，把 Qwen3.8 27B 固定到六个服务端点，比较不同量化精度。测试在 10 月 20 日进行；240 道主任务与另外 40 道乘法题分开计分，主任务没有检出显著精度差异。

对调用者更实用的办法是用自己的任务比较端点：硬件与服务软件都可能改变结果，fp4、fp8 标签只描述其中一个条件。平台作者有服务销售利益，这次实验的结论限于所测模型与任务。

AI / 02短讯

同一道题，MCP 吃掉 59,417 个词元，命令行只要 1,421

查一个仓库的最新版本和三个 bug，究竟要读多少上下文？OpenRouter 的作者实测比较了 GitHub MCP、命令行与技能三种做法。其 Sonnet 样本中，命令行用了 1,421 个输入词元，技能用了 3,315 个，默认工具全部装载的 MCP 则用了 59,417 个；工具说明之外，返回的完整对象也是负担。

实验使用 GitHub MCP server v2.0.2，每种组合运行三次取中位数，执行日是 10 月 20 日。缩小工具集合、限制返回字段，是减少上下文用量的两个检查点；这组比较只覆盖上述任务。

60 个请求挂了 23 个：被限流时，先看它让你等多久

OpenRouter 的批处理教程给出一个失败样本：60 个请求用默认重试，最后仍有 23 个失败；作者改为按响应给出的额度重置时间等待后，该次批次全部完成。

教程使用 openai Python SDK 3.26.1 经 OpenRouter 调用。遇到限流，先读响应里的等待提示，再安排下一次请求，可以减少无效重试；这次成功记录来自平台作者实测。
