ChatGPT 替你挑好商品，付款仍要你确认

Wallet 将选购与结账接在一起，却仍把最后一次授权留给用户。支付令牌减少了卡片资料的传递，收货信息和商品选择则是另外两件需要核对的事。

保存一次卡片，仍要逐笔同意

商品、总价、付款卡片——据 TechCrunch 的 Sarah Perez 报道，这是 ChatGPT Wallet 在结账前让用户检查的三项内容。代理可以帮人选购并处理订单，付款时仍需要用户通过 Face ID、指纹等安全检查确认。[1]

OpenAI 的公告把顺序写得更明确：先由用户批准这一次购买，支付网络再提供令牌，用来替代真实卡片资料。保存卡片减少的是重复填写，每一笔付款的确认仍然保留。用户同意过一次购物，不等于代理从此可以自行花钱。[2]

首批入口是 dots，范围限于美国境内年满 18 岁、持有合资格美国发行卡片的部分 ChatGPT Pro 用户。Decrypt 的 Jose Antonio Lanz 也指出，这一流程在 dots 对话中提供，不能把它理解为普通 ChatGPT 聊天已全面开放购物付款。[2][3]

令牌减少卡号暴露，订单仍需检查

按照 OpenAI 的说明，代理和商家不会拿到用户的真实卡号等卡片资料，款项仍记到所选卡片。TechCrunch 同时指出，配送仍要把收货地址和联系信息交给商家。因此，付款资料暴露较少，并不意味着整次交易匿名。[1][2]

用户仍要看买的是哪一件、数量是否正确、总价是否符合预期。安全地传递一笔付款，与挑中合适商品，需要分别判断。逐次确认给这些核对保留了一个停顿：代理把选择整理为具体订单，人再决定是否让它发生。

商品出现问题以后，交易关系也没有全部转交给代理。OpenAI 表示，用户直接与商家交易，定价、履约、退货和客服仍由商家负责；卡片既有奖励与符合条件的争议保障保留。付款入口更集中，不会消除消费者与商家、发卡机构之间的后续沟通。[2][3]

预先给出预算，还在未来计划里

OpenAI 计划让用户按金额、品类或时间段设置条件，预先允许代理完成符合规则的购买。TechCrunch 与 Decrypt 均将其写为未来能力，当前不能据此认为用户已经能设一个月度预算，便让代理持续自行下单。[1][2][3]

这一区别影响使用方式：现在，人面对的是一笔已列出内容的交易；如果未来能够预授权，人首先要定义的则是一组可以重复执行的条件。金额上限能限制花费，却无法单独说明商品是否适合、替代品是否可接受。后面这些问题，还需要具体规则和实际使用来回答。

商家覆盖也是限制。OpenAI 说明，一些网站会阻止代理访问，支付风控也可能把合法购买拦下，造成拒付或取消订单。能启动结账流程，不等于所有网站都会接受，也不保证一笔订单最终成功。[2][3]

这些说明尚不能给出实际交易成功率，本文也没有进行交易测试。对首批用户而言，具体变化是选购与结账进入同一条代理对话流程；最后的商品、总价和卡片确认，仍是决定这笔钱是否花出去的那一步。

datasette-llm 新增兼容端点，本地模型可接入数据查询代理

开发者 Simon Willison 发布 datasette-llm 0.1a11，为 Datasette 的模型配置增加 OpenAI 兼容端点。其示例把 Datasette Agent 接到 LM Studio 上运行的本地模型；Ollama、llama.cpp 等使用兼容接口的服务也可作为配置对象。选择本地端点仍需自行运行模型和准备算力，插件不会替用户完成部署。这是开发者发布说明与演示，本刊未复测；它与 llama.cpp 1.0 的版本治理是两件事。
